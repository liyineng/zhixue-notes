- Preserve existing uploads, notebooks, notes and model settings. Back up the local database before migrations. Keep migrations compatible with existing databases.
- Restrict retrieval to the current notebook and explicitly selected sources. An empty selection must never fall back to other notebooks.
- The user requests a GitHub backup after every completed update. After relevant checks pass, commit and push the finished change to the configured origin. Do not leave a completed update only in the local checkout. If pushing fails, report the failure accurately and retain the local commit.
- Keep databases, uploads, backups, API keys, environment files and personal presentation artifacts out of Git. They are intentionally ignored.
- Ask the user before adding optional new product features. Notebook organization, searching imported sources, saving answers as notes and Markdown export are already authorized.
- The user's current preference is to polish existing features without adding new ones. They have now explicitly requested that questions survive refreshing the page: persisting notebook-scoped questions, answers and citations is authorized. Webpage imports, flashcards and other new modules still require renewed authorization.
- Run `.venv/bin/python -m unittest discover -s tests -v` for backend behavior changes. Browser smoke tests are in `scripts/smoke-workspace.mjs`; they use temporary notebooks and mocked model answers and clean up their data.
- Keep vendor licenses intact. Do not rewrite third-party files to resolve formatting-only warnings.
- Image questions (upload, paste, OCR or configurable vision transcription, editable recognized text and notebook-scoped course answers) and per-citation colors are explicitly authorized. Image attachments and recognition results must survive refresh with the question; keep image files local and out of Git.
- Individual question/answer deletion and undo are authorized. Keep the latest five deleted exchanges per notebook for undo across refresh/restart, without limiting active history. Only purge older deleted exchanges and images no longer referenced by active or retained deleted exchanges.

Cancellation must stop the active backend job, retain a cancelled record and drafts, and prevent late results from overwriting cancellation.

- Limited automatic context for ordinary questions is explicitly authorized: use only the current notebook’s completed, active exchanges, keeping the newest turns within the connected model’s context budget after reserving space for the current question, source evidence, instructions and output. Detect provider capacity when available; clearly label a conservative fallback or manual override. Exclude deleted, failed, cancelled and pending exchanges. Explicit quote follow-ups use their selected snapshot instead. History is not source evidence and must not broaden retrieval scope.
- Generation-stage visibility is authorized. Report actual processing stages for questions, image recognition, retrieval, evidence selection and summaries; restore progress after refresh and stop progress updates after completion, failure or cancellation. Do not fabricate percentages or expose private model reasoning.
